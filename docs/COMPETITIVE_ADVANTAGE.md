# Competitive Advantage — AeroDriver (2026-11-22)

方法: 競争優位性プログラム。競合調査（有料・無料を問わず）→ お金の流れの
分解 → マスク思考法＋ソクラテス問答を、意味のある知見が出るまで反復
（2ラウンド実施）。判定の出発点は作成者の原則: 個人データを持たない／
提供はソフトウェアのみ（運営費を負担しない）／本体は無料。

## 市場とお金の流れ

| 競合 | 形態 | 収益モデル |
|---|---|---|
| Driver Booster（IObit） | 独自DB（無料版1,200万件超／Pro 1,800万件超を標榜） | 無料スキャン＋ Pro サブスク（1PC 定価 $39.95/年、プロモ $19.95 前後）。自社他製品の宣伝とカウントダウンセール。PUP 一覧で「aggressive notifications and bundling」と分類される |
| Driver Easy（Easeware） | 独自DB | 無料版は廃止。Pro $29.95/年（1PC）からの純サブスク |
| DriverPack Solution | 独自DB（110万パッケージ超） | 「無料」の対価はバンドルソフトの掲載料。Microsoft Defender が PUABundler:Win32/DriverPack として検出。拒否導線は Expert Mode の奥 |
| Avast Driver Updater 等 | AV スイートの追加販売 | サブスクのアップセル枠 |
| Snappy Driver Installer Origin | OSS（GPLv3）、オフライン driver packs | 完全無料・有料版なし・広告なし。有志のコミュニティプロジェクト。技術者の一括／オフライン配布が主用途 |
| Windows Update＋OEM 公式ツール | OS 内蔵／ハードウェア付属 | 無料。Microsoft が審査したドライバーを配る |

金が溜まる先は4つ。(a) 恐怖の換金 — スキャンが無害なバージョン差を
「古い／壊れている」と数え上げ、修正の先に課金壁を置く。
(b) バンドル掲載料 — 第三者ベンダーがインストール数に応じて払う。
(c) 不要な保守への家賃 — 「ドライバーは常に最新に」という前提自体が
専門家に否定されている作業への年額課金。(d) DB 維持費の回収 —
1,200万件規模のドライバーDBを保持・配信するコストが、上記 (a)〜(c) の
収益化を構造的に強制する。そして How-To Geek や XDA のような専門媒体は
カテゴリ全体を「使うな／scam に近い」と明言する水準にあり、
カテゴリ全体への不信が最大の市場環境になっている。

## 反復の記録

### ラウンド1 — 「最新が良い」を疑う

- 疑った前提: ドライバーは常に最新が良く、一括更新に価値がある。
- 消えたもの: 「更新の量・DB の件数」で競う軸。専門家の総意は
  「壊れていないドライバーは触るな。更新が要るのは GPU・セキュリティ
  修正・不具合対応のときだけ」であり、この軸では競う意味自体がない。
- 生き残ったもの: 更新の事故率を下げる側の価値 — 依存順序の計画、
  実ファイルのバックアップと世代ロールバック、WHQL/WDAC の警告、
  BYOVD の拒否。製品の重心は「更新する力」ではなく
  「更新しても壊れない／戻せる」にある。

### ラウンド2 — 「競合は同業者」を疑う（前提が崩れた）

- 本当の競合は (a) 何もしないこと（Windows Update が審査済み
  ドライバーを無料で配る）と (b) カテゴリ全体への不信だった。
- この市場では機能の多さも DB の大きさも勝敗を決めず、決めるのは
  「このツール自体が害をなさないことを、利用者が検証できるか」。
- 商用勢は「安全です」と約束できても、クローズドソース＋テレメトリ＋
  課金 SDK という収益構造のままでは証明できない。AeroDriver は
  絶対規則1（課金・テレメトリ禁止）を約束ではなく機械検証される
  不変条件として公開でき、ソース配布で誰でも監査できる。
- 副次的知見: 専門家がカテゴリを scam と呼ぶ市場では、看板で
  「driver updater」を名乗ること自体が負債になり得る。自己定義は
  「更新ツール」ではなく「入れる前に検証し、戻せるドライバー保守」に
  寄せるべき。

## 構造的優位

AeroDriver は、自前のドライバーデータベースを持たず Microsoft が
審査済みの配布経路（WUA／pnputil）だけを使うため運営費が発生せず、
その結果「課金・広告・バンドル・テレメトリを入れない」ことを規約では
なく機械検証される不変条件（絶対規則1）として公開でき、スキャンの
恐怖で課金へ誘導する収益構造を持つ同業には、この「証明可能な無害さ」を
真似できない。

補強する既存の実態:

- 絶対規則1は `tools/check-rule1.py` が外部ホスト許可リストと
  有償/テレメトリ SDK 拒否リストで機械検証し、`tools/verify-all.sh` の
  一部として常時回る。
- BYOVD 照合は全インストール／復元経路（CAB 展開後を含む）に適用され、
  `tools/check-blocklist-paths.py` が新しい経路の追加時に照合漏れを落とす。
- 署名検証は `WinVerifyTrust` による真正 Authenticode 検証で、
  検証→実行の間は `FileShare.Read` ロックでファイルの同一性を保つ。
- 更新は実ファイルのバックアップを取り、世代指定でロールバックできる。
  監査証跡（history）も残る。
- 作成者は利用者の個人データを持たない。テレメトリ自体が存在せず、
  ネットワーク接続先は許可リストで固定されている。

## 残りの機会（順位つき）

1. README の最初の画面に「決してしないこと」を明示する（本書と同梱で
   実施）。カテゴリ不信への回答が、現行では CLAUDE.md にしか無い。
2. 自己定義の再センタリング: 「driver management tool」から
   「入れる前に検証し、戻せるドライバー保守」へ。ただし絶対規則6
   （宣言と実装の一致）があるため、文言変更は実装監査とセットで行う。
3. 配布形態: 現状はソース配布のみで、初回成功までの距離がカテゴリで
   最も長い。署名済みバイナリの Releases 配布は距離を劇的に縮めるが、
   公開判断とコード署名証明書の費用が絡むため作成者の判断事項。
4. Windows 実機での受け入れ試験（`tools/verify-windows.ps1`）は
   バックログ既載の人間の作業で、製品の未検証部分として最大。
5. SDIO との棲み分けの明記: オフライン一括配布は SDIO の領分で、
   AeroDriver は「検証と復旧」の層に徹する。適用範囲を文書に書くことで
   大量展開用途への誤用を防ぐ。
6. winget への登録（SDIO は登録済み）。配布経路の標準化として、
   項目3の公開判断とあわせて検討する。
